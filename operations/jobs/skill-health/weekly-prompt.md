주간 스킬 건강검진을 수행하라.

목적: 최근 실제 사용에서 현재도 재현되는 스킬 계약·노출·라우팅 문제만 찾는다. 수정 전 문제나 현재 근거로 재확인되지 않은 관찰은 현행 결함으로 보고하지 않는다.

1단계는 반드시 아래 결정론적 collector 하나로 수행한다.

`/opt/homebrew/bin/python3 /Users/chumji/workspace/chumji-ops/jobs/skill-health/collect_candidates.py --openclaw-root /Users/chumji/.openclaw --days 7 --max-candidates 5 --max-sessions-per-candidate 3`

- collector JSON만 후보 선별 입력으로 사용한다.
- 별도로 전체 sessions.json, 전체 transcript, 도구 호출·오류 메타데이터를 열거·집계하지 않는다.
- collector 실패 시 범위를 넓혀 수동 전수검색하지 않는다. 한 번만 제한적으로 재시도하고, 복구되지 않으면 `주간 스킬 건강검진: 점검 저하(degraded)`로 보고한다.
- 후보가 없으면 현재 가시성·버전 확인에 필요한 최소 읽기 전용 점검만 하고 종료한다.

2단계 검증:
- collector가 고른 최대 5개 후보만 검토한다.
- 후보별 `session_refs` 최대 3개, 전체 최대 15개만 원문으로 확인한다.
- session-logs 규칙에 따라 trajectory를 제외하고 mirror/final 중복을 논리 응답 한 건으로 취급한다.
- reset/deleted 대화는 collector 범위 밖이다. 활성 원문만으로 판정할 수 없으면 확정하지 말고 `현재 미확인`으로 표시한다.
- claude-mem은 선택된 후보의 보조 검색에만 사용한다. 원 대화로 확인되지 않거나 철회·대체·신뢰도 하향된 관찰은 확정 근거로 쓰지 않는다.

현행성·원인 검증:
- 각 후보의 현재 SKILL.md 해시·수정시각 또는 Git 변경시각을 확인한다.
- 근거가 현재 버전 전인지 후인지, 이후 스킬·allowlist·카탈로그·라우팅·런타임·인증 구조가 바뀌었는지 확인한다.
- warning/broken은 현재 버전 또는 관련 수정 이후 독립 재발이 있거나, 현재 버전 이후 명시적 사용자 교정이 있을 때만 부여한다.
- 원인을 스킬 계약, 에이전트/호스트/계정/카탈로그 라우팅, 런타임/서비스, 단발 실행 실수로 분리한다. 스킬 계약 문제가 아니면 SKILL.md 수정을 권하지 않는다.
- 단발성 무영향 오발동이나 즉시 복구된 읽기 실패는 반복 또는 계약 공백이 입증되지 않으면 발견에서 제외한다.

실패·안전:
- 모든 도구 실패를 핵심/비핵심으로 분류해 건수를 기록한다.
- 핵심 실패는 더 단순한 명령으로 1회 재시도하고 안전한 대체 읽기 경로로 1회 확인한다.
- 미복구 핵심 실패로 후보 선별·원문 검증·현행성 확인에 공백이 남으면 `변경 없음`을 금지하고 degraded로 보고한다.
- 읽기 전용 smoke test만 허용한다. 예약·주문·발송·계정 변경·인증 복구·시크릿 변경·삭제·결제·외부 쓰기는 금지한다.
- live SKILL.md, Skill Workshop proposal, cron, Gateway, LaunchAgent, config, wiki를 수정하지 않는다.
- 원시 세션 내용, 시크릿, 개인정보, 내부 식별자를 보고서에 노출하지 않는다.

출력:
- 문제가 없고 검사 범위가 완전하면 `주간 스킬 건강검진: 변경 없음`으로 시작한다.
- 핵심 검사 공백이 있으면 `주간 스킬 건강검진: 점검 저하(degraded)`로 시작한다.
- 기간, collector의 활성 인덱스/원문 수, 후보 수, 실제 원문 검증 수, collector JSON 바이트, 도구 실패·복구·미복구 수를 적는다.
- 발견마다 대상, instruction layer, 근거 기간, 현행 버전 기준, 수정 후 재발, 철회·대체 확인, 원인 계층, 관찰/기대 차이, 심각도, 신뢰도, 최소 조치, 롤백 또는 다음 관찰 조건을 간결히 적는다.
- 사용 기록 없음만으로 제거를 권하지 않는다. 별도 회귀 테스트 추가를 기본 권고로 삼지 않는다.
- 사용자 승인 전에는 어떤 변경도 하지 않는다.
